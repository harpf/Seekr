# UI Translation Layer (i18n) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a lightweight UI translation layer to Seekr so every user-facing string in the Jinja shells (`document_search/web/templates/*.html`) and in `document_search/web/static/app.js` (toasts, labels, dynamic HTML) renders in the user's chosen language. Ship **English (`en`)** and **German (`de`)** catalogs, user/browser-selectable via a topbar language selector, persisted in `localStorage` and (optionally) server-side per user. The first server paint already uses the right language so there is no flash of the wrong language.

**Architecture:** JSON message catalogs live under `document_search/web/static/i18n/` (`en.json`, `de.json`). A tiny dependency-free JS module `document_search/web/static/i18n.js` loads the active catalog once, exposes a global `t(key, vars)` helper (with `{var}` interpolation and fallback to English, then to the key itself), and on load swaps text on every element carrying a `data-i18n` / `data-i18n-attr` / `data-i18n-placeholder` attribute. The active language is resolved at three layers, in priority order: (1) `localStorage['seekr_lang']`, (2) a server-rendered `<html lang>` / `<body data-lang>` value passed by Jinja, (3) the browser's `navigator.language`, falling back to `en`. The Jinja routes compute the initial `lang` from a per-user server preference (new additive `user_preferences` table) or the request `Accept-Language` header, and inject it into the template context so SSR and the client agree on the very first paint. Templates are marked up **page by page** (incremental, non-breaking — an un-marked string simply stays English). Dynamic JS strings move to `t()` calls keyed into the same catalogs.

**Tech Stack:** Python 3.11, FastAPI + Jinja2 (already present), SQLite (one additive table, same `_init_schema` migration pattern as the ACL/jobs plans), vanilla ES2017 JS (no framework, no build step), pytest. **No new third-party dependencies** (no Babel/gettext/`.po` tooling — see "Design decisions").

**Design decisions (stated up front):**
- **JSON catalogs, not gettext.** `.po`/`.mo` + Babel adds a compile step, a binary artefact, and a plural-forms machinery we do not need for two languages and a few hundred flat keys. Flat JSON catalogs are diffable, hot-editable, fetched once per page, and trivially testable for key-set parity. If the project later grows to many languages with complex pluralisation, revisiting gettext is a separate plan.
- **`data-i18n` attribute swap, not template-level `{{ _('...') }}`.** Server-side translation of every Jinja string would force the server to own the full catalog and re-render on language change. Instead the server only sets the *initial* `lang`; the client owns the catalog and can re-translate live (selector change) without a round-trip. The server still picks the correct first-paint language so there is no flash.
- **Namespaced dotted keys** (`nav.search`, `toast.signedIn`, `search.title`). Keeps the catalog self-documenting and groupable.
- **English is the fallback layer.** A missing `de` key falls back to the `en` value; a key missing from both falls back to the literal key string (visible-but-not-broken, and caught by the integrity test).
- **Server preference is optional and additive.** A new `user_preferences(user_id, key, value)` table stores `lang`. If a user has no row, the route falls back to `Accept-Language`. No existing behaviour changes for users who never touch the selector.

**Scope boundaries (out of scope for this plan, picked up later):**
- Translating **document content**, extracted text, AI-generated suggestions, or search snippets — only chrome/UI strings.
- Translating **server-side error `detail` strings** returned by the API (e.g. `"Session expired"`). The client maps a small set of *known* messages through `t()` where it already special-cases them (Task 4), but a full server-error i18n is a separate concern.
- Locale-aware **number/date/byte formatting** (`Intl.*`). Strings only; `formatBytes` etc. stay as-is.
- **RTL languages.** `en`/`de` are both LTR; no bidi work.
- A **third language** — the structure supports it (drop in `fr.json`, add to the selector + the catalog list), but only `en`+`de` ship here.
- Translating the **wiki/OpenAPI** embedded Swagger page (third-party rendered).

## Catalog conventions (locked)

- **Key format:** dotted namespace, `area.thing` — e.g. `nav.dashboard`, `auth.signIn`, `toast.tagsSaved`, `search.placeholderQuery`.
- **Interpolation:** `{name}` placeholders, replaced by `t(key, {name: value})`. Literal braces are not used in UI copy.
- **Attribute targeting in templates:**
  - `data-i18n="key"` → sets element `textContent`.
  - `data-i18n-placeholder="key"` → sets the `placeholder` attribute.
  - `data-i18n-title="key"` → sets the `title` attribute.
  - `data-i18n-html="key"` → sets `innerHTML` (use only for copy that legitimately contains markup; values must be author-controlled, never user data).
- **Selector languages list** lives in one place: `I18N_LANGS` in `i18n.js`.

        )

- [ ] **Step 3: Implement `document_search/web/i18n.py`**

```python
"""Server-side language resolution for the first server-rendered paint.

Single source of truth for which languages the UI ships. The JS layer
(`static/i18n.js`) mirrors this list; the catalog-integrity test keeps the
two in sync via the on-disk catalog files.
"""
from __future__ import annotations

SUPPORTED_LANGS: tuple[str, ...] = ("en", "de")
DEFAULT_LANG = "en"


def _parse_accept_language(header: str | None) -> list[str]:
    """Return base language codes from an Accept-Language header, highest-q first."""
    if not header:
        return []
    parts: list[tuple[float, str]] = []
    for token in header.split(","):
        token = token.strip()
        if not token:
            continue
        lang, _, qpart = token.partition(";")
        q = 1.0
        if qpart.startswith("q="):
            try:
                q = float(qpart[2:])
            except ValueError:
                q = 0.0
        base = lang.strip().lower().split("-")[0]
        if base:
            parts.append((q, base))
    parts.sort(key=lambda p: p[0], reverse=True)
    return [base for _, base in parts]


def resolve_lang(accept_language: str | None, preferred: str | None) -> str:
    """Resolve the active UI language.

    Priority: a valid stored `preferred` preference, then the best
    `Accept-Language` match, then DEFAULT_LANG.
    """
    if preferred and preferred in SUPPORTED_LANGS:
        return preferred
    for base in _parse_accept_language(accept_language):
        if base in SUPPORTED_LANGS:
            return base
    return DEFAULT_LANG
```

- [ ] **Step 3: Create `i18n.js`**

`document_search/web/static/i18n.js` — must be loaded **before** `app.js` on every page. It exposes `window.t`, `window.i18nReady` (a promise), and `window.setLang(lang)`.

```javascript
// Lightweight i18n layer: JSON catalog + t(key, vars) + data-i18n DOM swap.
// No build step, no framework. Loaded before app.js on every page.
(function () {
  'use strict';

  const I18N_LANGS = ['en', 'de'];     // mirror of web/i18n.py SUPPORTED_LANGS
  const DEFAULT_LANG = 'en';
  const STORAGE_KEY = 'seekr_lang';

  let _catalog = {};       // active language catalog
  let _fallback = {};      // English catalog (always loaded as fallback)
  let _lang = DEFAULT_LANG;

  function _normalize(lang) {
    if (!lang) return null;
    const base = String(lang).toLowerCase().split('-')[0];
    return I18N_LANGS.includes(base) ? base : null;
  }

  // Resolve initial language: localStorage > server-rendered data-lang > navigator > default.
  function _initialLang() {
    return (
      _normalize(localStorage.getItem(STORAGE_KEY)) ||
      _normalize(document.body && document.body.dataset && document.body.dataset.lang) ||
      _normalize(navigator.language) ||
      DEFAULT_LANG
    );
  }

  async function _fetchCatalog(lang) {
    const res = await fetch(`/static/i18n/${lang}.json`, { cache: 'no-cache' });
    if (!res.ok) throw new Error(`catalog ${lang} failed: ${res.status}`);
    return res.json();
  }

  // t('key', {name: 'x'}) -> string. Fallback: active -> English -> key.
  function t(key, vars) {
    let str = _catalog[key];
    if (str === undefined) str = _fallback[key];
    if (str === undefined) str = key;
    if (vars) {
      str = str.replace(/\{(\w+)\}/g, (m, name) =>
        Object.prototype.hasOwnProperty.call(vars, name) ? String(vars[name]) : m
      );
    }
    return str;
  }

  // Apply translations to every element carrying a data-i18n* attribute.
  function applyDom(root) {
    const scope = root || document;
    scope.querySelectorAll('[data-i18n]').forEach((el) => {
      el.textContent = t(el.getAttribute('data-i18n'));
    });
    scope.querySelectorAll('[data-i18n-html]').forEach((el) => {
      el.innerHTML = t(el.getAttribute('data-i18n-html'));
    });
    scope.querySelectorAll('[data-i18n-placeholder]').forEach((el) => {
      el.setAttribute('placeholder', t(el.getAttribute('data-i18n-placeholder')));
    });
    scope.querySelectorAll('[data-i18n-title]').forEach((el) => {
      el.setAttribute('title', t(el.getAttribute('data-i18n-title')));
    });
  }

  async function _load(lang) {
    _lang = _normalize(lang) || DEFAULT_LANG;
    // Always have English available as the fallback layer.
    if (!Object.keys(_fallback).length) {
      _fallback = await _fetchCatalog(DEFAULT_LANG);
    }
    _catalog = _lang === DEFAULT_LANG ? _fallback : await _fetchCatalog(_lang);
    document.documentElement.setAttribute('lang', _lang);
    if (document.body) document.body.dataset.lang = _lang;
    applyDom(document);
  }

  // Public: change language at runtime (selector). Persists locally + server (best effort).
  async function setLang(lang) {
    const norm = _normalize(lang);
    if (!norm) return;
    localStorage.setItem(STORAGE_KEY, norm);
    await _load(norm);
    // Best-effort server persistence; ignore failures (e.g. logged out).
    try {
      const token = localStorage.getItem('documentSearchToken');
      if (token) {
        await fetch('/api/preferences/lang', {
          method: 'PUT',
          headers: { 'X-Auth-Token': token, 'Content-Type': 'application/json' },
          body: JSON.stringify({ lang: norm }),
        });
      }
    } catch (_) {}
    // Reflect selection in any rendered selector(s).
    document.querySelectorAll('[data-lang-select]').forEach((sel) => { sel.value = norm; });
  }

  function currentLang() { return _lang; }

  // Wire up any topbar language selector.
  function _initSelectors() {
    document.querySelectorAll('[data-lang-select]').forEach((sel) => {
      sel.value = _lang;
      sel.addEventListener('change', (e) => setLang(e.target.value));
    });
  }

  // Expose globally for app.js and inline handlers.
  window.t = t;
  window.i18nApplyDom = applyDom;
  window.setLang = setLang;
  window.i18nCurrentLang = currentLang;

  // Boot: load the catalog before app.js renders dynamic content.
  window.i18nReady = _load(_initialLang())
    .then(_initSelectors)
    .catch((err) => { console.error('i18n init failed', err); });
})();
```

## Task 6: Catalog-integrity pytest (key parity + template coverage)

**Files:**
- Create: `tests/test_i18n_catalogs.py`

This is the safety net that compensates for the absence of a JS test runner: it asserts (1) `en.json` and `de.json` have identical key sets, (2) every `{var}` placeholder set matches between languages per key, (3) every `data-i18n*` key referenced in any template exists in **both** catalogs, and (4) catalogs are valid UTF-8 JSON.

- [ ] **Step 1: Write the test**

Create `tests/test_i18n_catalogs.py`:

```python
import json
import re
from pathlib import Path

import pytest

I18N_DIR = Path("document_search/web/static/i18n")
TEMPLATE_DIR = Path("document_search/web/templates")
EN = I18N_DIR / "en.json"
DE = I18N_DIR / "de.json"

# data-i18n, data-i18n-html, data-i18n-placeholder, data-i18n-title
_DATA_I18N_RE = re.compile(r'data-i18n(?:-(?:html|placeholder|title))?\s*=\s*"([^"]+)"')
_VARS_RE = re.compile(r"\{(\w+)\}")


def _load(path: Path) -> dict:
    return json.loads(path.read_text(encoding="utf-8"))


def test_catalogs_are_valid_json():
    assert isinstance(_load(EN), dict)
    assert isinstance(_load(DE), dict)


def test_catalogs_have_identical_key_sets():
    en, de = _load(EN), _load(DE)
    en_keys, de_keys = set(en), set(de)
    missing_in_de = en_keys - de_keys
    missing_in_en = de_keys - en_keys
    assert not missing_in_de, f"keys missing in de.json: {sorted(missing_in_de)}"
    assert not missing_in_en, f"keys missing in en.json: {sorted(missing_in_en)}"


def test_placeholders_match_per_key():
    en, de = _load(EN), _load(DE)
    mismatches = {}
    for key in en:
        en_vars = set(_VARS_RE.findall(en[key]))
        de_vars = set(_VARS_RE.findall(de.get(key, "")))
        if en_vars != de_vars:
            mismatches[key] = (sorted(en_vars), sorted(de_vars))
    assert not mismatches, f"placeholder mismatch per key: {mismatches}"


def _template_keys() -> set[str]:
    keys: set[str] = set()
    for tpl in TEMPLATE_DIR.glob("*.html"):
        text = tpl.read_text(encoding="utf-8")
        keys.update(_DATA_I18N_RE.findall(text))
    return keys


def test_every_template_key_exists_in_both_catalogs():
    en, de = _load(EN), _load(DE)
    used = _template_keys()
    missing_en = sorted(k for k in used if k not in en)
    missing_de = sorted(k for k in used if k not in de)
    assert not missing_en, f"data-i18n keys used in templates but absent from en.json: {missing_en}"
    assert not missing_de, f"data-i18n keys used in templates but absent from de.json: {missing_de}"


def test_no_empty_translations():
    for path in (EN, DE):
        cat = _load(path)
        empty = sorted(k for k, v in cat.items() if not str(v).strip())
        assert not empty, f"{path.name} has empty values for keys: {empty}"
```

## Notes for the executing agent

- **Why the page routes resolve from `Accept-Language` only (not the stored preference):** the HTML routes are unauthenticated — the auth gate is client-side and there is no token at render time. The server gives a *good-enough* first paint from the browser header; the client then refines from `localStorage` (which reflects the last explicit choice and, after login, the server-stored value synced via the login response). This keeps SSR simple and avoids a per-request DB lookup on every page load. If you later move auth server-side (cookie session), wire the stored preference into `_page_lang` then.
- **Load order matters.** `i18n.js` MUST be the `<script>` before `app.js` in every template, and `bootstrap()` MUST `await window.i18nReady`. Otherwise the first dynamic render (results, tables) can paint untranslated. The manual check in Task 5 Step 4 asserts the script order.
- **`fetch('/static/i18n/...')` cache:** use `cache: 'no-cache'` (as written) so catalog edits show up on reload during development. For production you may add a cache-busting query (`?v=<build>`); not required here.
- **Incremental markup is intentional.** You do not need to tag 100% of strings in one pass. Anything untagged stays English and is harmless. The integrity test only constrains keys you *do* reference. Prefer correctness (every tagged key present in both catalogs) over breadth.
- **Do not translate `showToast(e.message, ...)`.** Those carry server/exception text. Translating them would require server-error i18n, which is explicitly out of scope. The handful of *known* client-side messages (session expired, etc.) are the only ones moved to `t()`.
- **German copy review:** the German strings here are reasonable but should get a native-speaker pass. The integrity test guarantees *structural* parity (keys + placeholders), not translation quality — flag the catalog for human review.
- **Keep `I18N_LANGS` (JS) and `SUPPORTED_LANGS` (`web/i18n.py`) in sync.** Adding a third language means: a new `<lang>.json` (same keys — the integrity test will force parity once you add it to the glob-checked set), a new `<option>` in each selector, and the code constant in both places. Consider a follow-up test asserting the JS `I18N_LANGS` array literal matches `SUPPORTED_LANGS` if drift becomes a problem.
- **`ON CONFLICT ... DO UPDATE` requires the `PRIMARY KEY(user_id, key)`** declared in Task 1 — that is what makes `set_preference` an idempotent upsert. Don't drop the composite PK.
