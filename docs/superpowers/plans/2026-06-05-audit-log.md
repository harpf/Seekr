# Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Seekr a persistent, admin-viewable audit trail (ROADMAP P4 "Full audit log") that records *who* did *what* to *which* target — search, file open, upload, document move/reindex/delete, user CRUD, config save, and SSL changes — satisfying the traceability/provenance goals in AGENTS.md. The acting user always comes from the existing `require_user` / `require_admin` helpers; nothing is logged for unauthenticated callers.

**Architecture:** One new SQLite table `audit_log` (actor, action, target, detail JSON, IP, timestamp). `SqliteStore` gets two helpers — `record_audit(...)` (one insert) and `list_audit(...)` (filterable, paginated read). The web layer instruments the state-changing and sensitive-read routes with **explicit** `db.record_audit(...)` calls (see "Key design decisions" for why explicit beats middleware here). A single admin endpoint `GET /api/audit` exposes the log with filters and pagination, and a new Config → **Audit** tab renders it as a table. All schema changes are additive and run inside the existing `_init_schema` migration pattern in `SqliteStore`.

**Tech Stack:** Python 3.11, SQLite, FastAPI, pytest, vanilla JS (no framework — matches the existing `app.js`). No new third-party dependencies.

**Scope boundaries:**

In scope:
- `audit_log` table + indexes, added to `_init_schema` (idempotent, like the ACL/jobs tables).
- `SqliteStore.record_audit` (insert) and `SqliteStore.list_audit` (filter by user/action/target/date range, paginated).
- Explicit audit instrumentation at: `/api/search`, `/api/files/open`, `/api/upload`, `/api/documents/{id}/reindex`, `/api/ai/reorganize/apply` (document move), config save (`/api/config`), user CRUD (`/api/users` POST/PUT/DELETE + change-password), and SSL changes (`/api/ssl/generate`, `/api/ssl/upload`).
- `GET /api/audit` — admin-only, filterable, paginated.
- Config → Audit tab (read-only table with filter inputs + pagination).
- Tests: actions write audit rows with the correct actor/target; `GET /api/audit` is admin-only and filters correctly (via `TestClient`).

Out of scope (deferred to later plans):
- A dedicated "document delete" route — Seekr currently has **no** standalone `DELETE /api/documents/{id}`; deletions happen via `/api/index/cleanup` (bulk remove-missing) and via re-index/move. We instrument `cleanup` as a `documents.cleanup` action and the move path as `document.move`; a true per-document delete endpoint, if added later, gets its own `document.delete` action then.
- Tamper-evidence (hash-chaining / signing) of audit rows.
- Log retention / rotation / export to SIEM.
- Per-row redaction policies beyond the search-query privacy note (see "Notes for the executing agent").
- Auditing read-only listing endpoints (`/api/folders`, `/api/users` GET, `/api/status`) — these are low-signal and would flood the log.

## Key design decisions (locked)

- **Explicit `record_audit` calls, NOT middleware.** A `BaseHTTPMiddleware` (like `_SecurityHeaders`) can see the path, method, status, and IP — but it *cannot* see the meaningful target id (which `document_id` was opened, which `user_id` was deleted, what the search query was) without re-parsing the request body and the route's path params, and it runs *after* the route may have raised. Explicit calls placed at the success point of each route capture the real target id and the real actor (already resolved by `require_*`). This is the recommended approach and the one this plan implements.
- **Actor is always the `require_*` return value.** Both helpers return the authenticated `user_id`. We never log an action for a request that failed auth (the `require_*` call raises 401/403 before the audit line is reached).
- **`detail_json` is a JSON string**, holding action-specific context (e.g. `{"query": "...", "result_count": 5}` for search, `{"path": "..."}` for open). Kept small; never stores file contents.
- **IP comes from `request.client.host`**, captured via a tiny `_client_ip(request)` helper that tolerates a missing client (returns `"unknown"`). Routes that don't already take a `Request` param gain one (FastAPI injects it; it's backward-compatible).
- **`action` is a stable dotted string** (`search`, `file.open`, `upload`, `document.reindex`, `document.move`, `documents.cleanup`, `user.create`, `user.update_role`, `user.delete`, `user.change_password`, `config.save`, `ssl.generate`, `ssl.upload`). Stable strings let the admin UI filter by a known vocabulary.
- **`target_type` / `target_id`** identify the object acted upon: `("document", "42")`, `("user", "7")`, `("config", null)`, `("ssl", null)`, `("query", null)`. `target_id` is TEXT (some targets have no integer id).
- **Auditing never breaks the request.** `record_audit` is best-effort: if the insert fails, the route's primary result must still return. The `_audit(...)` wrapper swallows and logs exceptions.
- **`created_at` is ISO-8601 UTC**, matching every other timestamp column in the schema.

```python
    def record_audit(
        self,
        actor_user_id: int | None,
        action: str,
        target_type: str | None = None,
        target_id: str | int | None = None,
        detail: dict | None = None,
        ip: str | None = None,
    ) -> int:
        """Insert one audit row. Best-effort: callers wrap this so a logging
        failure never breaks the audited operation.

        `target_id` is coerced to TEXT (some targets are non-integer); `detail`
        is JSON-encoded. Returns the new row id.
        """
        now = datetime.now(tz=UTC).isoformat()
        cur = self.conn.execute(
            "INSERT INTO audit_log(actor_user_id, action, target_type, target_id, "
            "detail_json, ip, created_at) VALUES(?,?,?,?,?,?,?)",
            (
                actor_user_id,
                action,
                target_type,
                None if target_id is None else str(target_id),
                json.dumps(detail) if detail is not None else None,
                ip,
                now,
            ),
        )
        self.conn.commit()
        return int(cur.lastrowid)

    def list_audit(
        self,
        actor_user_id: int | None = None,
        action: str | None = None,
        target_type: str | None = None,
        date_from: str | None = None,
        date_to: str | None = None,
        limit: int = 50,
        offset: int = 0,
    ) -> list[dict]:
        """Return audit rows newest-first, with optional filters and pagination.

        Each returned dict includes a decoded `detail` key (the parsed
        `detail_json`, or `None`) plus the joined `actor_username` for display.
        """
        clauses: list[str] = []
        params: list = []
        if actor_user_id is not None:
            clauses.append("a.actor_user_id = ?")
            params.append(actor_user_id)
        if action:
            clauses.append("a.action = ?")
            params.append(action)
        if target_type:
            clauses.append("a.target_type = ?")
            params.append(target_type)
        if date_from:
            clauses.append("a.created_at >= ?")
            params.append(date_from)
        if date_to:
            clauses.append("a.created_at <= ?")
            params.append(date_to)
        where = ("WHERE " + " AND ".join(clauses)) if clauses else ""
        sql = (
            "SELECT a.id, a.actor_user_id, u.username AS actor_username, a.action, "
            "a.target_type, a.target_id, a.detail_json, a.ip, a.created_at "
            "FROM audit_log a LEFT JOIN users u ON u.id = a.actor_user_id "
            f"{where} ORDER BY a.id DESC LIMIT ? OFFSET ?"
        )
        params.extend([limit, offset])
        rows = self.conn.execute(sql, tuple(params)).fetchall()
        out: list[dict] = []
        for r in rows:
            d = dict(r)
            d["detail"] = json.loads(d["detail_json"]) if d["detail_json"] else None
            out.append(d)
        return out

    def count_audit(
        self,
        actor_user_id: int | None = None,
        action: str | None = None,
        target_type: str | None = None,
        date_from: str | None = None,
        date_to: str | None = None,
    ) -> int:
        """Count audit rows matching the same filters as `list_audit` (used for
        pagination totals)."""
        clauses: list[str] = []
        params: list = []
        if actor_user_id is not None:
            clauses.append("actor_user_id = ?")
            params.append(actor_user_id)
        if action:
            clauses.append("action = ?")
            params.append(action)
        if target_type:
            clauses.append("target_type = ?")
            params.append(target_type)
        if date_from:
            clauses.append("created_at >= ?")
            params.append(date_from)
        if date_to:
            clauses.append("created_at <= ?")
            params.append(date_to)
        where = ("WHERE " + " AND ".join(clauses)) if clauses else ""
        sql = f"SELECT COUNT(*) FROM audit_log {where}"
        return int(self.conn.execute(sql, tuple(params)).fetchone()[0])
```

    import logging as _logging
    _audit_log = _logging.getLogger("seekr.audit")

    def _client_ip(request: Request | None) -> str | None:
        if request is None or request.client is None:
            return None
        return request.client.host

    def _audit(
        actor_user_id: int | None,
        action: str,
        target_type: str | None = None,
        target_id: str | int | None = None,
        detail: dict | None = None,
        request: Request | None = None,
    ) -> None:
        """Best-effort audit write. Never raises into the calling route."""
        try:
            store().record_audit(
                actor_user_id=actor_user_id,
                action=action,
                target_type=target_type,
                target_id=target_id,
                detail=detail,
                ip=_client_ip(request),
            )
        except Exception:
            _audit_log.exception("Failed to write audit row for action=%s", action)

```javascript
// ── Audit log ──────────────────────────────────────────────────────
let _auditOffset = 0;
const _AUDIT_LIMIT = 25;
let _auditTotal = 0;

function _auditFilters() {
  const action = document.getElementById('auditActionFilter')?.value || '';
  const from = document.getElementById('auditFrom')?.value || '';
  const to = document.getElementById('auditTo')?.value || '';
  const params = new URLSearchParams();
  params.set('limit', String(_AUDIT_LIMIT));
  params.set('offset', String(_auditOffset));
  if (action) params.set('action', action);
  // Date inputs are yyyy-mm-dd; widen to full-day ISO bounds.
  if (from) params.set('date_from', `${from}T00:00:00+00:00`);
  if (to) params.set('date_to', `${to}T23:59:59+00:00`);
  return params;
}

async function loadAudit() {
  try {
    const params = _auditFilters();
    const data = await api(`/api/audit?${params.toString()}`);
    _auditTotal = data.total;
    renderAuditTable(data.items);
    updateAuditPager();
  } catch (e) {
    setText('auditResult', e.message, 'err');
  }
}

function auditFirstPage() { _auditOffset = 0; loadAudit(); }

function auditPage(dir) {
  const next = _auditOffset + dir * _AUDIT_LIMIT;
  if (next < 0 || next >= _auditTotal) return;
  _auditOffset = next;
  loadAudit();
}

function updateAuditPager() {
  const from = _auditTotal === 0 ? 0 : _auditOffset + 1;
  const to = Math.min(_auditOffset + _AUDIT_LIMIT, _auditTotal);
  setText('auditSummary', `${from}–${to} of ${_auditTotal}`);
  const prev = document.getElementById('auditPrev');
  const next = document.getElementById('auditNext');
  if (prev) prev.disabled = _auditOffset === 0;
  if (next) next.disabled = _auditOffset + _AUDIT_LIMIT >= _auditTotal;
}

function _auditTarget(row) {
  if (!row.target_type) return '—';
  return row.target_id ? `${escHtml(row.target_type)} #${escHtml(row.target_id)}` : escHtml(row.target_type);
}

function _auditDetail(row) {
  if (!row.detail) return '';
  try { return escHtml(JSON.stringify(row.detail)); } catch (e) { return ''; }
}

function renderAuditTable(items) {
  const el = document.getElementById('auditTable');
  if (!el) return;
  if (!items.length) {
    el.innerHTML = '<p class="muted" style="font-size:.82rem;">No audit entries match the current filters.</p>';
    return;
  }
  el.innerHTML = `<table class="u-table"><thead><tr>
      <th>When (UTC)</th><th>Actor</th><th>Action</th><th>Target</th><th>IP</th><th>Detail</th>
    </tr></thead><tbody>${
    items.map(row => `<tr>
      <td class="muted" style="font-size:.75rem;white-space:nowrap;">${escHtml((row.created_at || '').replace('T', ' ').slice(0, 19))}</td>
      <td>${escHtml(row.actor_username || (row.actor_user_id != null ? `#${row.actor_user_id}` : '—'))}</td>
      <td><span class="badge badge-n">${escHtml(row.action)}</span></td>
      <td style="font-size:.8rem;">${_auditTarget(row)}</td>
      <td class="muted" style="font-size:.78rem;">${escHtml(row.ip || '—')}</td>
      <td style="font-size:.75rem;"><code>${_auditDetail(row)}</code></td>
    </tr>`).join('')
  }</tbody></table>`;
}
```

> `escHtml` and `setText` already exist in `app.js` (used by `renderUserTable`); reuse them. The Audit tab is `admin-only hidden`, so it is revealed by the existing `showAdminUI()` call for admins.

## Notes for the executing agent

- **PRIVACY — logging search queries.** The `search` action stores the raw query string in `detail_json`. Queries can be sensitive (names, case numbers, medical terms). This is an intentional traceability trade-off for an internal/self-hosted tool, but call it out: (1) the audit log is admin-only at the API and UI layers; (2) if deployment policy forbids storing query text, change the search audit `detail` to `{"query_length": len(req.query), "result_count": len(output)}` — keep the *event* and the *actor* but drop the query body. The endpoint, table, and UI all keep working unchanged. Do not store query text in a deployment subject to GDPR data-minimisation without a documented retention/justification.
- **Why explicit calls, not a middleware:** a middleware sees the path and status but not the resolved `document_id` / `user_id` / query, and it runs after the route may have raised. Explicit `_audit(...)` calls at each success point capture the real target and the real actor (already produced by `require_*`). This is deliberate (see Key design decisions) and matches the spec's recommendation.
- **`request: Request` param additions are backward-compatible.** FastAPI injects the `Request` automatically; adding it to a route signature does not change the wire contract and does not affect existing tests that post the same JSON. If an existing test breaks after you add `request: Request`, the cause is elsewhere — read the failure; do not delete the param.
- **Best-effort logging is a feature, not a bug.** `_audit` swallows exceptions on purpose: an audit-table hiccup must not take down search or uploads. The swallow path logs via the `seekr.audit` logger so failures are still visible in server logs.
- **No standalone document-delete route exists today.** Deletions happen through `/api/index/cleanup` (bulk remove-missing) which is audited as `documents.cleanup`. If a future plan adds `DELETE /api/documents/{id}`, give it a `document.delete` action with `target_type="document"`, `target_id=document_id`, mirroring the move instrumentation.
- **HA endpoints are intentionally un-audited here.** `/api/ha/*` authenticate with an API key, not a session user, so there is no `actor_user_id` to record. Auditing them needs an "api-key principal" concept and is deferred. Do not pass a fabricated user id.
- **`target_id` is TEXT on purpose.** Some targets (config, ssl, query, documents-bulk) have no integer id; `record_audit` coerces ints to strings so `list_audit` comparisons are consistent.
- **Keep `detail_json` small.** Never store file contents, password material, full certificate PEMs, or whole config blobs — store identifiers and changed-key names only.
